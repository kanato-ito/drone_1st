# ステップ③a 制御の信号の流れ（姿勢推定 → PID → ミキサー → 推力換算 → PWM）

IMU の値から、4つのモーターに出すデューティ比を計算するところまでを作った。状態遷移・見張り役・非常時降下・WDT は次回（③b）。
設計の正本は設計メモ rev22（2026-11-08）。メモにないことは「提案」と書いた。

## 2. 単位の決め方（2026-11-08 オーナー了承）

**推力も、ロール・ピッチ・ヨーの指令も、すべて「1モーターあたりの推力[g]」でそろえる。**

- `thrust_g` = 4つのモーターの平均推力（ホバリングなら機体重量÷4 に近い値）
- `torque_g[roll/pitch/yaw]` = その軸の指令。「モーター同士の推力差の片側ぶん」。ミキサーが ± で配る
- 各モーターの推力 = `thrust_g` + roll符号×ロール + pitch符号×ピッチ + yaw符号×ヨー

理由: メモのミキサーは「全体の推力 ± ロール ± ピッチ ± ヨー」と推力同士の足し引きで、推力換算も[g]だった。ヘッダの N・N·m のままだと、アーム長・ヨーの反トルク係数・[N]と[g]の換算を持ち込むだけで得るものがない。ゲインは実機で合わせるので[g]で足りる。
名前は `thrust_n`→`thrust_g`、`torque_nm`→`torque_g` に直した。角度は rad、角速度は rad/s、加速度は g のまま。

## 3. 各モジュールの式

### 3.1 姿勢推定（`attitude.c`）

1周期（約8サンプル）をまとめて1回更新する（サンプルごとに三角関数を呼ぶと重いため）。

- 加速度から見た傾き: `roll_acc = atan2(ay, az)`、`pitch_acc = atan2(-ax, sqrt(ay²+az²))`
- ジャイロで進める: 機体の角速度 (p,q,r) をオイラー角の変化率に直し、`角度_予測 = 角度 + 変化率 × dt`
- 相補フィルタ: `角度 = 予測 + k × (加速度の角度 − 予測)`、`k = dt / (τ + dt)`。τが大きいほどジャイロを信じる（初期値 0.5s、仮）
- ヨーはジャイロの積分だけ。±180°に折り返す。磁気がないのでゆっくりずれる（受け入れる）
- 座標: 姿勢推定には `imu_mount_apply`（`params.imu_mount.axis_map`）で機体の軸へ並べ替えた値が入る。IMU基板は x右・y前・z上、機体は x前・y左・z上（右手系）。`axis_map = {2, -1, 3}`（設計メモで確定、2026-11-08）。水平なら加速度は (0,0,+1g)。roll+ は左側が上がる向き、pitch+ は機首が下がる向き、yaw+ は上から見て反時計回り

バイアスと静止判定:
- 静止 = 「ジャイロの平均からのばらつき ≤ 0.02 rad/s」かつ「| |加速度| − 1 | ≤ 0.05g」が 1秒続く（途中で外れたら数え直し）
- 静止と確定している間だけバイアス平均を更新。アームでは `attitude_set_bias_locked(true)` で固定
- 提案1: 静止判定に「ジャイロ平均の大きさ ≤ 0.1 rad/s」も足した。一定の速さで回り続けるとばらつきが0になり、回転をバイアスと思い込むため（試験で見つけた）
- 提案2: 加速度の大きさが 1g から 0.3g 以上ずれる周期は、加速度による補正をしない（飛行中の加速・振動で角度を引きずらないため）

### 3.2 2段PID（`controller_pid.c`）

```
外側（角度）: 目標角速度[rad/s] = PID(目標角度 − 角度)
内側（角速度）: 指令[g]        = PID(目標角速度 − 角速度)
```

- 3軸とも同じ形。ヨーの角度誤差は ±180° に折り返す（最短回り）
- 内側を外側よりはっきり速くする。調整は内側から（kp → ki の順）。外側の ki, kd は 0
- 積分: アーム時に0。目標推力が `i_enable_thrust_g`（仮3g）を超えている間だけためる。I項の寄与を `i_limit`（内側 roll/pitch で 1g = 出力上限6gの約17%）で止める
- 微分は測定値の変化に対して取る（目標が変わっても跳ねない）。変化量は ±180° に折り返す（ヨーが +180°→−180° をまたいでも跳ねない）。初期値は kd=0

### 3.3 ミキサー（`mixer.c`）

`モーターi = 全体 + sign[i][roll]×R + sign[i][pitch]×P + sign[i][yaw]×Y`、結果は 0 〜 最大推力[g] に収める。

はみ出したときの優先（ロール・ピッチ最優先）:
1. ヨーを削る（収まる最大の割合まで、必要なら0まで）
2. 4つを同じだけ上下にずらす（全体推力を犠牲にする）
3. モーター同士の差が最大より大きくて収まらないときだけ、ロール・ピッチを縮める（比率は保つ）

結果には `yaw_scale` `shift_g` `rp_scale` が入る（どの手順が働いたか）。

**モーターの番号・位置・回転方向（設計メモで確定、2026-11-08）**: 右前M2・左前M4・右後ろM1・左後ろM3。上から見て M1とM4（対角）が時計回り、M2とM3が反時計回り。符号は `params.c` の `mixer_sign` の表1か所だけ:

| | roll | pitch | yaw |
| --- | --- | --- | --- |
| M1 右後ろ CW | −1 | +1 | +1 |
| M2 右前 CCW | −1 | −1 | −1 |
| M3 左後ろ CCW | +1 | +1 | −1 |
| M4 左前 CW | +1 | −1 | +1 |

`mixer_sign_table_valid` が「3列の和が0、列同士が直交（対角が同じ回転方向）」を検査し、ホスト試験 `physical` が「傾けると戻す向きのモーターが上がる」を確かめる。

### 3.4 推力 → デューティ（`thrust_model.c`）

`デューティ = 欲しい推力[g] ÷ (9.4 × 電池電圧[V])`（HW実測: 推力 ≒ 9.4×デューティ×電圧）。折れ線テーブルは使わない。

- ミキサーと別ファイルにした理由: ミキサーは「配分」、ここは「モーターと電池の物理」。係数 9.4 や電圧補償を直しても、ミキサーの試験に影響しない
- ミキサーの上限は `最大推力 = 9.4 × 電圧`（デューティ100%の推力）。電圧が下がると上限も下がる
- 電圧は `voltage_min_calc_v`（3.0V）未満・NaN を 3.0V に丸める。割り算が暴れないためだが、実電圧より低く見る分デューティは大きめに出る（提案）
- 電池電圧は GP28(ADC2) → 分圧比（仮置き 2.0、**TODO: HW設計書で確認**）→ 時定数1sのローパス

### 4.2 ブレッドボード（`control_bench`）

ビルド（モーターPWMは出ない）:

```sh
cd firmware
cmake -B build -G Ninja -DPICO_SDK_PATH=<pico-sdk のパス>
ninja -C build        # build/control_bench.uf2 ができる
```

書き込みと配線は `docs/step2_imu_fifo.md` と同じ（IMU配線のみ。モーターは接続しなくてよい）。

**PWM出力について（安全）**: 既定では **PWM を出さない**。デューティを計算して表示するだけで、ピンは 0 のまま。出す場合だけ `-DFC_BENCH_PWM_ENABLE=ON` を付ける。

> **警告: PWMを有効にするときは必ずプロペラを外す。** 符号表は確定したが、実機で回す向き・どれが強く回るかはまだ確かめていない。有効ビルドでもデューティは 0.30 で頭打ち（`FC_BENCH_DUTY_MAX`）、傾き60°超・INT1途絶・読み出し失敗で全部0にし、電源を入れ直すまで再開しない。

手順:
1. 起動後、ボードを机に置いて静止させる。`WAIT` 行の `hold` が1.0sになり水平（10°以内）なら `RUN` に変わる（バイアス固定・積分0・ヨーの目標=この向き）
2. `RUN` で静止のまま数十秒見る
3. 手で傾けて戻す（ロール・ピッチ）

表示の例: `[  12s] RUN  att[deg] r=+0.10 p=-0.05 y=+0.02 bias[dps]=(...) pid[g] T=10.0 r=... duty=(...) sat=0 Vbat=3.80(仮:未接続) proc_us avg/max=../.. over=0 TMO=0 ERR=0 PWM=OFF`

- 電池が未接続（ADCが2V未満）のときは換算に 3.8V の仮値を使い、`(仮:未接続)` と出す
- スロットルは固定の仮値 `FC_BENCH_THRUST_G` = 10g/モーター
- `MISS` = 読み終わってもINT1がHighのままだった回数（次の立ち上がりが来ないので、待たずにすぐ読み直す）。`RESC` = INT1を5ms待っても来ず、ピンがHighだったので読んで救出した回数。`OVR` = FIFOあふれ、`TRUNC` = 1回で読み切れず残した回数。`INT1pin` = 表示時点のピンのレベル
- INT1が来ずピンもLowのとき（IMUが止まった）は `TRIP` になり、毎秒 `IMU診断: WHO_AM_I=… 設定の不一致=…` を出す。WHO_AM_I がNGなら配線・電源、OKで設定が不一致ならIMUがリセットされた（電源の瞬断など）
- 静止のまま置くと、pid の r/p がゆっくり増えて I の上限（1g）で止まり、デューティが開いていく。これは正常: 台上ではモーターが機体を動かさないので、水平からのわずかなずれ（取り付けや机の傾き）を I 項がため続ける（実機では機体が傾いて戻るので、ずれは0へ向かう）

### 4.3 合格条件

| # | 条件 |
| --- | --- |
| 1 | 静止で roll/pitch ≈ 0（±1°）。bias が数 dps 以内で安定。yaw のずれが遅い |
| 2 | 手で傾けると roll/pitch が追従し、符号が合う（左側を上げると roll+、機首（基板のy+側）を下げると pitch+）。戻すと0へ戻る |
| 3 | 傾けると PID 出力とデューティが「戻す向き」に動く（左側を上げると r が負になり、左のM3・M4のデューティが下がる。機首を下げると p が負になり、前のM2・M4が上がる）。傾けないときの4つのデューティは近い値（個体差は I 項で吸収する前提） |
| 4 | `proc_us` の最大が 1064µs に余裕をもって収まる（目安: 最大800µs以下、平均はその半分以下）。`over=0`、`TMO=0`、`ERR=0`、`OVR=0`。`MISS`/`RESC` は0が理想（出ても止まらず続けば可。数を記録） |
| 5 | 電池をつないだとき、Vbat が実測（テスターで電池を測る）と合う → 合わなければ分圧比を直す |

ループ時間の中身は FIFO 読み出し約160µs（ステップ②で実測）＋ 姿勢・PID・ミキサー。**実機の値はまだ測っていない**（このドキュメントの時点でビルドとホスト試験のみ確認）。

## 6. 提案・迷った点（メモにない決め）
