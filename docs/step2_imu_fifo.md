# ステップ② IMUのFIFO読み出し（ブレッドボード試験）

IMU（LSM6DSV16X）のFIFOを INT1 で起こして読めるか、ブレッドボードで確かめる。作ったのは次の4つ。

| ファイル | 役割 |
| --- | --- |
| `firmware/src/port_pico/imu_lsm6dsv16x.c` | IMUドライバ（SPI・設定・INT1・FIFO読み出し）。レジスタの出典は各定義のコメントに書いた |
| `firmware/src/port_pico/clock_wdt_pico.c` | 時計だけ。WDTは空のスタブ（ステップ③で作る） |
| `firmware/apps/imu_fifo_test.c` | 試験アプリ。1秒に1行、統計を表示する |
| `firmware/CMakeLists.txt` | ライブラリ `fc_core` / `fc_port_pico` と試験アプリ `imu_fifo_test`。あとで本体 `drone_fw` を足せる形 |

## 1. 配線（以前の GP16〜19 から基板のピンへ）

以前の WHO_AM_I 試験は GP16〜19 だった。**基板のピンは違う**ので、配線を付け替える。`board_pins.h` の値と同じにする。

| Pico 2 W | 信号 | IMUモジュールの端子 |
| --- | --- | --- |
| GP22 | SCK | SCL（SCK） |
| GP7 | MOSI | SDA（SDI/MOSI） |
| GP20 | MISO | **SA0**（SDO/SA0。右列の一番上） |
| GP27 | CS（GPIOで操作） | CS |
| GP26 | INT1（入力） | INT1 |
| 3V3(OUT) | 電源 | 3V3（VCC） |
| GND | GND | GND |

- 秋月 AE-LSM6DSV16X では、シルクの「SDO」は補助SPIの SDO_AUX で、MISO ではない。MISO は必ず「SA0」の穴につなぐ（以前の試験で GP16 につないでいた穴）。
- INT1 が今回の新しい配線。ここが外れていると「タイムアウト」が出続ける（ピンはプルダウンしてあるので浮かない）。
- ジャンパが短いほど SPI は安定する。以前 8MHz 指定（実際は7.5MHz）で誤り0だったのと同じ条件に近づける。

## 2. ビルドと書き込み

**VS Code の Pico 拡張**: `firmware/` フォルダを開く → 「Compile Project」→ 出来た `build/imu_fifo_test.uf2` を使う。

**コマンドライン**:

```sh
cd firmware
cmake -B build -G Ninja -DPICO_SDK_PATH=<pico-sdk のパス>
ninja -C build
```

**書き込み**: BOOTSEL ボタンを押しながら USB をつなぐ → `RP2350` というドライブが出る → `build/imu_fifo_test.uf2` をコピー。
そのあと USB のシリアルモニタ（115200bps、設定は何でもよい）を開く。**開くまで起動が止まって待つ**ので、開かないと何も出ない。

## 3. 出力の読み方

起動時に出るもの:

```
SPI: 指定 8000000 Hz -> 実際 7500000 Hz
imu_init: OK (0)
設定の読み戻し (読んだ値 / 期待値):
  0x0F WHO_AM_I          = 0x70 / 0x70  OK
  ...
```

全部 `OK` ならレジスタに書けている。`NG` の行があればその設定が効いていない。

そのあと1秒に1行:

```
[  12s] INT1= 940.0Hz words avg/min/max=16.0/16/17 pairs=7520 OVR=0 TMO=0 ERR=0 MISS=0 read_us avg/max=170/190 gyro[dps]=(...) accel[g]=(...) |a|=1.001
```

| 項目 | 意味 | 合格の目安（数値の幅は提案） |
| --- | --- | --- |
| INT1 | その1秒のINT1立ち上がり回数 | 約940Hz（920〜980）。**約1880Hzなら** WTMを「組」と読み違えている |
| words avg/min/max | 1回の読み出しで読んだワード数 | 平均約16（16〜18）、最小16 |
| pairs | その1秒に取れたジャイロ+加速度の組 | 約7500（ODR 7.68kHz、実測は約7519Hz） |
| OVR | FIFOあふれの回数（累計） | 0 |
| TMO | INT1が5ms来なかった回数（累計） | 0 |
| ERR | 読み出し失敗の回数（累計） | 0 |
| MISS | 読み終わってもINT1がHighのままだった回数（累計） | 記録（少ないほど良い） |
| read_us | `imu_read_fifo` の所要時間（平均/最大） | 記録（目安は約160µs。1.04msに収まる判断材料） |
| gyro / accel | 最新の1組 | 静止で gyro はほぼ0付近、**\|a\| が約1.00g（0.95〜1.05）** |

静止のまま数十秒見て、OVR・TMO・ERR が0のままで INT1 が約940Hzなら合格。read_us と MISS は記録しておき、設計メモの確定条件（1.04msに収まるか）の材料にする。

## 4. 設定値を選んだ理由

| 設定 | 値 | 理由 |
| --- | --- | --- |
| SPI | モード0、8MHz指定（実7.5MHz） | 以前の試験で誤り0。実クロックは `spi_init()` の戻り値で表示する |
| ODR（ジャイロ・加速度） | 7.68kHz、高性能モード | 設計メモのとおり。ループの周期は IMUの時計で決まる |
| BDR（FIFOに入れる速さ） | 両方7.68kHz | ODRと同じにして、全サンプルをFIFOに入れる（間引かない） |
| FIFOモード | Continuous（stream） | 読むのが遅れても古いものから捨てて動き続ける。止まらない |
| **WTM = 16** | 16ワード | WTMの単位は**ワード**（TAG+6バイトで1ワード）。ジャイロ1+加速度1で2ワードなので、16ワード＝8組。8にすると4組で約1880Hzになる（architecture.md A#4） |
| INT1 | FIFOウォーターマーク（INT1_CTRL の FIFO_TH） | DRDY（1サンプルごと）だと7.68kHzで割り込みが来て重すぎる。8組ごとなら約940Hz |
| BDU | 有効 | 上位・下位バイトの片方だけ新しい値を読んでしまうのを防ぐ。FIFOでは本来影響は小さいが、他のレジスタを読むときの保険 |
| フルスケール | ジャイロ±2000dps、加速度±16g | **提案（メモ未記載）**。機体が速く回ってもはみ出さず、着地の衝撃も測れる値。分解能は少し粗くなる（姿勢制御に足りるかは飛行試験で再検討） |
| ISR は記録だけ | 時刻と回数を残すだけ | SPIで約160µs読む間、ほかの割り込みを止めてしまうため。読みはメインループで行う |
| INT1取りこぼしの確認 | 読み終わりでピンを見る | 立ち上がりエッジ割り込みなので、読み終わってもHighのままだと次のエッジが来ない（architecture.md #10）。試験アプリは `MISS` として数え、タイムアウト時もHighなら読んで救出する |
| 1回で読むワード数 | `DIFF_FIFO` 全部（最大64ワード） | 遅れて溜まった分も1回で空にする |
| CSのまとめ方 | 既定は1ワードごと | 下の「確認できなかったこと」を参照 |

## 5. 確認できなかったこと・提案

- **FIFOを複数ワード、1回のCS区間で続けて読めるか**: ST公式ドライバは「TAGから7バイトを1回読む」形だけで、7バイト読んだあとアドレスが0x78に折り返すかは分からなかった。そのため既定は1ワードごとにCSを切る形（`IMU_FIFO_WORDS_PER_CS=1`）。データシートで折り返しが確認できたら、`firmware/CMakeLists.txt` の `fc_port_pico` に `target_compile_definitions(fc_port_pico PRIVATE IMU_FIFO_WORDS_PER_CS=16)` を足して read_us を比べられる。間違っていればタグが想定外になり `ERR` が増える。
- FIFOあふれは `FIFO_OVR_IA` に加えてラッチ版も見ている（提案）。`OVR` が静止中なのに増え続けるなら、ラッチ側を外す。
- 軸の向き・ジャイロのオフセット補正はまだしない（architecture.md #14）。今の値はセンサーの軸のまま。
